🥧 Pi Agent: Architecture & Runtime Explorer

An interactive guide breaking down the modular engine behind the Pi CLI coding agent

🧠 pi-agent-core Engine

The state machine orchestrating the think-act-observe cycle. Houses the streaming engine, tool dispatching, and conversation lifecycle hooks.

🤖 pi-ai Model Hub

Unified client translating prompts and tool definitions across OpenAI, Anthropic, Gemini, Ollama, and local models seamlessly.

🎯 pi-coding-agent App CLI

The full developer application containing filesystem tools (read, edit, write, bash), extension runners, skills loaders, and prompt builders.

🪑 pi-tui Terminal UI

High-performance terminal rendering engine utilizing differential updates to draw reactive markdown, spinners, and stream buffers without flickering.

📦 pi-durable Persistence

Reliable JSONL transcript storage and session branch management. Allows instant pause, resume, branching, and context compaction.

🔌 chord Host Link

Typed host RPC and plugin communication backbone enabling hot-reloading extensions, cross-process tool calls, and sandboxing.

📖 read

Paginates through files with line numbers. Reads raw text or downsamples images to keep LLM context light.

✂️ edit

Surgical find-and-replace. Requires the AI to match the exact characters on disk. If whitespace or lines don't match, the edit is safely rejected.

📝 write

Creates new files from scratch or writes complete replacements atomically.

⚡ bash / powershell

Executes shell commands with process timeouts, output truncation guards, and background daemon task tracking.

Pi's Philosophy

  • Minimalist: No forced planning agents or complex sub-agent swarms out of the box.
  • Your Machine, Your Rules: Runs under your local user permissions without hidden sandboxes unless you ask for one.
  • Monorepo Reusability: You can import @earendil-works/pi-agent-core directly into your own Node/TypeScript app without the CLI.

Steering vs Follow-Up

Steer: Injects an urgent message mid-run before the next turn.

Follow-up: Waits quietly until all current tool calls and assistant turns are completely idle before triggering the next task.
